经营数据分析 Agent 小队

一套七角色 AI 编队的经营分析流水线方案：从数据源治理到复盘沉淀的八步闭环，把经营分析从「人肉流水线」变成「越跑越顺的 Agent 流水线」。

版本 · 方案 v3.6 关键词 · 多 Agent 协作 分析流水线 提示词工程

我在搭什么：把分析做成体系

经营分析原本是一条人肉流水线：拉数、清洗、算指标、写结论、做图表，全靠一个人在不同工具间切换，质量靠细心，进度靠加班。

这套方案把整条流水线拆成七角色 AI 编队：每个 Agent 只做一件事、有明确的输出物与质量门，由「调度 Agent」当总导演统一派活。人从执行者变成验收者——只在关键节点确认口径、拍板结论。

七角色体系

  • 调度 Agent（总导演）：用户唯一入口，对齐需求、分发任务、把关质量门、交付任务卡
  • 数据预处理 Agent（地基）：从数据源拉取、清洗、口径标准化，输出下游可直接使用的分析数据集
  • 经营分析 Agent（分析师）：按「整体→人员→客户→问题→建议」五段框架做归因分析，只写文字不画图
  • 核查 Agent（守门员）：数据交叉核验、口径检查，有差异就打回重算
  • 客户速览 Agent（业务专家）：对 Top 重点客户做深度洞察补充
  • 可视化 Agent（设计师）：按内置标准图表库出图，画板 SVG 可再编辑，自动规避历史踩坑
  • 复盘与知识沉淀 Agent（教练）：任务复盘、沉淀规则、优化各 Agent 提示词，让体系持续进化

八步流水线

所有任务严格按八步流转，上一环节质量门不通过绝不进入下一环节：需求对齐 → 数据预处理 → 经营分析 → 数据核查（未过则打回迭代，通常 1-3 轮）→ 客户深挖 → 可视化 → 交付（附极简任务卡：总耗时、环节耗时占比、人工介入次数）→ 复盘沉淀。

三个设计要点

核查是质量门，不是装饰。核查 Agent 与分析师分离，利用生成方与检查方天然的不对称；「通过/不通过」标准明确，不通过就打回，直到核查通过才进下一环节。

评估是副产品，不是 KPI。各环节自动采集指标（数据完整率、错误数及类型分布、环节耗时），复盘 Agent 汇总——不额外填表、不打分，攒够三次同类任务自动出趋势与优化清单。

持续进化。每次任务完成触发复盘：新口径写进预处理规则库、新踩坑写进可视化自检清单、新分析逻辑写进分析师提示词——体系自己越跑越顺。

提示词工程：角色 + 铁律

方案最有参考价值的部分是每个 Agent 的完整提示词框架。它不写「你要好好分析」这种空话，而是把业务规则固化成铁律：「所有数字必须来自标准化数据集，不自行累加」「客户按集团口径合并，不拆零散小品牌」「只说业务语言，不说环比上升 XX% 这种空话」——每一条铁律都来自真实踩过的坑。

可复用的部分

  • 角色分工：生成方与检查方分离、调度单一入口——任何有质量要求的 AI 流水线都可借鉴
  • 流程控制点：八步每一环的输入/输出/质量门定义清楚，可整体迁移到其他分析场景
  • 口径管理：财年口径、客户归一、同期对比等规则写成铁律，沉淀为长期有效的规则库
  • 评估闭环：指标随流程自动采集，不增加额外工作量
