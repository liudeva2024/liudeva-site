播客对谈追踪

追踪关注对象以播客对谈为主的长期观点表达——一条三模块自动化闭环：每日检索 → 自动转写 → 卡片推送，让「这个人最近在想什么」不再靠刷到才算数。

时间 · 2026.10 关键词 · 自动化 内容追踪 反馈闭环

我在搭什么

一个人真正的长期观点，常常散落在各期播客对谈里。它们没有被整理、没有被推送，甚至听过就忘——想持续知道一个人在想什么，只能靠手动搜、手动听、手动记，坚持不了几天。

这套系统把整件事拆成一条流水线：定时检索关注对象的对谈节目、核实发布日期后入库；转写专员把音频转成保留原话的文字版；转写完成即推送消息卡片，卡片上的按钮把「感兴趣 / 读完」反馈直接写回表内。人只做判断，剩下的交给系统。

三个模块，一条流水线

模块一 · 检索入库（每日 02:00）：按关注清单逐人检索——小宇宙、Apple Podcasts、喜马拉雅、B 站视频访谈、通用搜索，多路找「人物 + 播客 / 对谈 / 嘉宾 + 日期窗口」。命中后逐条打开单集页，以页面上的实际发布日期为准写入对谈表，不凭搜索结果的时间戳入库；当天无命中就把窗口拉长到近 30 天补检索。

模块二 · 转写专员（每日 05:00）：aily 工作伙伴只做一件事——把待转写的播客链接变成保留原话的文字版云文档。解析单集页 og:audio 取音频直链（小宇宙是 302 重定向，必须跟随，否则拿到 0 字节文件）→ 上传飞书妙记转写 → 按编辑规则生成文字版 → 回填链接。单次最多处理 3 条、串行执行、完成一条立即回填。

模块三 · 卡片推送（转写完成即推）：多维表 Workflow 在「转写文字」回填后推送消息卡片，五字段标题加粗：关注对象 / 对谈背景 / 主要议题 / 核心观点 / 值得关注。卡片带三个按钮——标记感兴趣、标记读完、打开文字版，点击即写回表内，不离开聊天就完成一轮筛选。

三个设计细节

断点续传。每条转写完成立即回填链接，任务中断后下次从剩余记录继续，不重跑、不丢单——长任务的可用性不赌一次跑完。

纠错词库。转写里的错词沉淀为一张跨场景纠错权威源表：错误写法 → 正确写法，带类型、置信度、状态、适用场景。转写、纪要、字幕、文稿共用同一份词库，高置信词条强制替换——错误修一次，处处生效。

串行限流。单次最多 3 条、串行处理，避开妙记并发与配额限制；失败不阻塞，记录原因次日重试，配额始终可控。

质量底线：转写保留原话

转写是这套系统里最容易被「聪明地毁掉」的一环，所以规则写死：保留原话是第一优先级，不概括、不缩写、不改写说话人的用词和语气；只修高置信度错别字、口吃重复与断句标点；听不清处保留原样并标注，绝不脑补。正文不加时间戳、段落之间真正空一行、姓名标注只在换人时出现一次且加粗。

经验沉淀

做对的：把「追踪一个人」拆成检索、转写、反馈三个独立模块，各自有明确边界和回填链路，任何一环失败都不拖垮整条线；反馈闭环让系统不只是「收集」，而是「越用越知道你要什么」。

踩的坑：302 重定向不跟随会拿到 0 字节；妙记转写有并发与配额限制，必须串行限流；按钮跳转要用链接字段的链接属性引用，直接取链接值类型会报错。

你关注的人在想什么，不该靠缘分听见。
